DEFINITION

大型主機現代化，第一步該做什麼？

第一步是產出可信的現況規格：說清楚現在的程式在做什麼、資料結構長什麼樣子、批次作業怎麼串。不論後續是 COBOL 轉 Java、轉平台還是上雲，都需要這份基準。

LISA 是奧洛（Aurobase）AURO NEXUS 產品家族的大型主機現代化工具。它讀取 COBOL、PL/I、組合語言、JCL、COPYBOOK 與 IMS 原始碼，以確定性解析產出繁體中文規格書，每一個欄位與每一段邏輯都標明原始碼檔案與行號，同一份原始碼每次產出相同結果。

適合誰

  • 銀行、保險與公部門資訊單位主機系統仍在運作，但文件過時、熟悉的人員陸續退休。
  • 現代化專案的 PM 與架構師改寫或轉換之前，需要一份可驗收的現況規格。
  • 稽核與風控要確認系統文件與實際程式一致。

THE PROBLEM

主機現代化卡住的地方，通常在第一步

改寫、轉平台、上雲都是後面的事；在那之前，得先說得清楚現在的系統在做什麼。

01

文件早已過時

規格書與實際程式脫節多年，真正可信的只剩原始碼，但能讀懂的人越來越少。

02

人工盤點又慢又貴

一支程式動輒數千行，資料結構散在 COPYBOOK、流程散在 JCL，靠人工整理曠日費時。

03

AI 摘要無法查證

把程式丟給通用 AI 產生說明，內容看似合理，卻無從確認哪一句出自哪一行，難以作為驗收依據。

LISA 產出的規格書，每一句都能對回原始碼。解析採確定性方法，結果可重現、可逐行查證。

CAPABILITIES

從原始碼到規格書

原始碼以文字檔交付即可，不需連線到主機環境。

多語言解析

  • COBOL、PL/I 與組合語言（HLASM）程式流程解析。
  • COPYBOOK 資料結構：欄位、層級、型別、長度。
  • JCL 批次作業：步驟、程式、資料集；另解析 CICS、BMS／MFS 畫面與內嵌 SQL。

IMS 資料庫存取

  • PSB 程式規格區塊解析。
  • DL/I 呼叫擷取：程式對哪些區段做了哪些存取。

逐項出處

  • 中介模型為每個欄位、每段邏輯記錄原始碼檔案與行號。
  • 規格書上的任何一項都能對回原文查證。

繁體中文規格書

  • 自動產出繁體中文規格書，章節依程式、資料結構、批次作業組織，可匯出 Word。
  • 提供影響分析與資料血緣，可作為現代化專案的現況基準與驗收依據。

確定性、可重現

  • 結構事實由確定性解析產生，同一份原始碼每次產出相同結果。
  • 若啟用 AI 撰寫敘述段，經 Forge 治理並標示「待複核」。
  • 支援 EBCDIC 主機字元集（CCSID 037、500、1140）。

API 介接

  • 以 API 提供解析與產出規格書，可納入既有的盤點或文件流程。

WHAT'S DIFFERENT

差異點

可追溯的規格，不是 AI 摘要

規格書由解析結果結構化產出，每一項都附原始碼位置。

原始碼不離開機房

結構解析不需呼叫外部 AI 服務，原始碼可以留在客戶環境內處理。

繁體中文為第一語言

規格書以繁體中文產出，用語貼近台灣金融與公部門的文件習慣。

SCOPE

範圍界定

以下是目前版本的範圍，導入前會在規劃階段逐項確認。

1

第一階段聚焦在「讀懂」

LISA 目前交付的是解析與規格書；自動改寫為其他語言不在本階段範圍。

2

繁體中文主機碼頁尚未支援

含繁體中文的主機碼頁（CCSID 937）尚未支援，需以客戶實際樣本開發與驗證。

3

尚未有正式部署

LISA 已完成解析與規格書產出，尚未在客戶正式環境部署，導入時以 POC 驗證。

FAQ

常見問題

LISA 支援哪些主機語言？

COBOL、PL/I、組合語言（HLASM）、JCL、COPYBOOK、IMS 的 PSB 與 DL/I 呼叫，以及 CICS、BMS／MFS 畫面與內嵌 SQL。

LISA 會把 COBOL 轉成 Java 嗎？

目前階段聚焦在「讀懂」：產出可逐行查證的繁體中文規格書，作為 COBOL 轉 Java 或其他現代化方案的現況基準與驗收依據。

規格書是 AI 寫的嗎？

結構事實不是。欄位、邏輯與批次關係由確定性解析產生，每一項都標明出自原始碼哪個檔案、第幾行；若啟用 AI 撰寫敘述段，會經 Forge 治理並標示待複核。

原始碼需要上傳到雲端嗎？

不需要。LISA 可部署在企業自有環境，部署設定預設封鎖對外連線，原始碼不離開機房。
